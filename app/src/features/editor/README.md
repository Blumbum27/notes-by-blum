# Компоненты редактора (зона B)

`index.ts` экспортирует независимые части для композиции маршрутом с оболочкой C:

- `EditorTools`: `state: EditorToolState`, `onChange(state)` — центральная группа.
- `EditorToolPanel`: те же props, `eraserAutoReturn`, `onEraserAutoReturnChange(value)` и `onClear()` — настройка принадлежит shared settings, подтверждение очистки — владельцу документа.
- `EditorTextFormat`: `textFormat: TextFormat`, `setTextFormat(format)` — формат текста.
- `EditorHistory`: `onUndo()`, `onRedo()`, imperative ref `update({canUndo,canRedo})`; история обновляется внутри капсулы, без React-рендера оболочки на каждом штрихе.
- `EditorPageRibbon`: manifest `notebook`, `tools`, `readOnly`, `fingerDrawing`, доступная `width`, `activePage`, `command`; callbacks `onActivePageChange(index)`, `onHistoryChange({canUndo,canRedo})`, `onObjectsChange(pageId,objects)`; необязательные `horizontal` и `textFormat`.

`command` имеет уникальный `id` и `action: undo | redo | clear | viewport` и адресуется активной странице. `viewport` возвращает центр видимой части страницы через `onVisibleCenter` для вставки фото. Штрихи не передаются JS: нативный модуль сериализует и атомарно пишет `.drawing` в последовательной utility-очереди при паузе, завершении штриха, снятии канваса и уходе приложения в фон. Чтение drawing использует ту же очередь. `saveAllCanvases()` завершает редактирование текста и дожидается фоновой записи всех живых документных канвасов, исключая превью. Ошибка чтения блокирует перезапись повреждённого drawing. При смене страницы вызывается этот барьер; миниатюры обновляются адресно по сигнатурам страницы и времени изменения drawing. `clearCanvasPage(path)` очищает страницу у живого нативного владельца или атомарно пишет пустой drawing в той же очереди для неживой страницы.

Владелец manifest последовательно сохраняет изменения объектов через `repository.saveNotebook`: репозиторий атомарно пишет `pages/<pageId>.json`. Маршрут передаёт оболочку в `NotebookScreen({ frame })` через `EditorFrameProps`; editor не импортирует editor-shell. `NotebookScreen` читает блокнот по `id` маршрута и монтирует `NotebookEditor key={notebook.id}`: документы изолированы, а при смене вкладки прежний редактор остаётся на экране, пока читается следующий. Жест закрытия zoom-перехода отключён, чтобы не мешать рисованию. Контракт включает `onClearPageAt(index)` для адресной очистки из сайдбара. Пресеты записываются атомарно через `.tmp → move` с debounce; автовозврат ластика хранится только в shared settings.

Нативный модуль принимает `pageWidth/pageHeight` в точках страницы, `rotation`, `packagePath`, `background`, `objects`, `textFormat`. Формат текста дополнительно допускает `underline/strikethrough` (необязательные поля, обратная совместимость существующих документов). `onObjectsChange` возвращает объекты, `onToolEnd` сообщает конец PencilKit-жеста. Единственный renderer создаёт `thumbnails/<pageId>.png` и `cover.png` для ленты, панели и библиотеки. Он сохраняет пропорции изображения фона и текстовые подчёркивание/зачёркивание; поворот применяется ко всей странице как в живом канвасе.

## Полный перенос редактора — 14 ноября 2026 (актуальное состояние)

Раздел заменяет устаревшие утверждения ниже о составе панели, ширине бумаги и ленте страниц.

- Лента — один `ScrollView` с масштабом всего документа (1–4×), без постраничных `ScrollView` и `FlatList`. Активная страница определяется по центру видимой области в `onScroll`; прокрутка пальцем никогда не вызывает программный `scrollTo`, поэтому можно остановиться посередине предыдущей страницы. Переход из боковой панели, поиска и «Перейти к странице» — `scrollRequest` с анимированной прокруткой. Живые канвасы — ±1 страница, миниатюры — ±5, дальше пустые заготовки. Бумага вписывается по высоте (не уже 530 pt), промежуток 14 pt; горизонтальный режим — постраничный.
- Центральная группа: Лассо | Письмо, Ластик, Фигуры, Клейкая заметка, Изображение, Текст, Лазерная указка | Линейка. Иконки 18 pt в зоне 42×44, у каждого инструмента свой цвет и подложка выбранного состояния.
- Письмо: ручка (перьевая / шариковая / кисть, чувствительность к нажиму, стабилизация), карандаш, маркер, лента (скрывает записи, касание показывает и снова скрывает), ручка для фигур («Держать для привязки»). У каждой группы свои толщины и палитра; цвет — сетка 8×3, системный ColorPicker, добавление и удаление цветов.
- Фигуры: от руки (распознавание линии, эллипса/круга, треугольника, ромба, прямоугольника, многоугольника), ломаный и изогнутый соединители, квадрат, круг, треугольник, ромб, скруглённый прямоугольник. Готовая фигура — обычный штрих PencilKit, поэтому работают undo, ластик и лассо. `ShapeGeometry.inkPointScale` переводит ширину инструмента в размер точки штриха.
- Клейкие заметки (10 цветов) и лента — объекты страницы (`sticky`, `tape`) с поворотом; лазерная указка (точка/линия) ничего не сохраняет и плавно гаснет.
- Ластик: точный / стандартный / для штрихов, автовозврат, очистка страницы. Команда `erase` с `inks` удаляет штрихи выбранных типов (оболочка: «Удалить элементы»).

Не переносятся: стикеры и GIF из магазина Goodnotes (нужен backend), диктовка и записи, Time Keeper, окно масштаба. Нет прямоугольного лассо и фильтров захвата лассо: штатный `PKLassoTool` их не поддерживает.

## Полировка инструментов — ноябрь 2026

Миниатюрами владеет только редактор. Одна последовательная очередь выполняет нативный барьер сохранения, ожидает manifest-записи и обновляет изменённые страницы по сигнатурам; удалённые ID исключаются из кеша. После каждого успешного адресного рендера увеличивается `EditorFrameProps.thumbnailRevision`, который оболочка использует для обновления изображений. Изменения оболочки, объектов и окончание штриха проходят через ту же очередь. Ошибка миниатюры изолирована от сохранения и навигации: следующая страница продолжает обрабатываться, неизменённая ошибочная сигнатура не повторяется, понятное предупреждение показывается один раз для документа за запуск приложения. Повреждённый drawing не заменяется.

Центральная группа содержит только иконки Лассо, Письмо, Ластик, Изображение и Текст; accessibility labels сохранены. История и подпанели позиционированы поверх ленты, без изменения её геометрии. На ширине менее 760 pt подпанель переносится на второй плавающий ряд, чтобы не перекрывать историю. Бумага шириной до 530 pt, промежуток 7 pt, без скругления, фон `#F4F6F5`. Индикатор страницы расположен слева внизу.

У ручки, карандаша и маркера независимые палитры и выбранные толщины. Файл `editor-presets-v2.json` читается асинхронно; запись отложена на 600 мс и завершается при unmount. Ручка: 0,2 / 0,2 / 0,6 мм (дублирование из спецификации сохранено), карандаш: 0,3 / 0,9 / 1,5 мм, маркер: 2,3 / 4,6 / 6,9 мм. Преобразование в координаты PencilKit: `pt = mm × 72 / 25,4`, то есть ручка 0,57 / 0,57 / 1,70 pt, карандаш 0,85 / 2,55 / 4,25 pt, маркер 6,52 / 13,04 / 19,56 pt. Это номинальная ширина инструмента, не обещание физической ширины штриха при любом zoom/давлении. Перьевая — `.fountainPen`, шариковая — `.monoline`, кисть — `.pen`; превью рисуется настоящим `PKDrawing`. Неподдерживаемые PencilKit слайдеры давления, формы наконечника и стабилизации не показаны.

Точный и стандартный ластики используют `PKEraserTool(.bitmap)` с ширинами 5 / 20 / 40 и 20 / 40 / 80 pt соответственно. Ластик для штрихов — `.vector`, без выдуманного фильтра по типу чернил. Размеры bitmap не зависят от номинальных мм ручки. Автовозврат обрабатывается по `onToolEnd`; повторный тап основного ластика скрывает/показывает подпанель. Лассо — штатный `PKLassoTool` и его системное меню, без неработающих настроек.

Текст создаётся касанием; пустой новый draft не записывается в manifest и не создаёт шаг отмены. Существующее поле с удалённым текстом удаляется из manifest. Изменения текста фиксируются при завершении редактирования и перед явным сохранением. Синяя рамка, клавиатура и редактирование — `UITextView`. Форматирование: системный ColorPicker, размер (slider/stepper), шрифт, B/I, выравнивание. Семейства «Современный» / «Классический» / «Технический» соответствуют System / Georgia / Menlo; неизвестные оригинальные шрифты Goodnotes не выдаются за точные. Панель остаётся у верхнего края, а не привязана к текстовому полю; размер не содержит поля ручного числового ввода. Фото вставляется через системный picker в центр видимой части текущей страницы, с сохранением пропорций и возвратом предыдущего инструмента. Объекты доступны для перемещения в режиме Лассо; меню фото содержит масштабирование и удаление.

Ячейка страницы обёрнута в `React.memo`, события имеют стабильные callback-адаптеры. Undo/redo bridge отправляет событие только при изменении доступности, не на каждом изменении drawing. PDF/картинка фона не перечитываются из prop setter при неизменных значениях. Численные FPS/latency не измерялись; структурная проверка не заменяет профилирование.

Известное согласованное отступление от референса 31b: капсула форматирования текста остаётся сверху области страниц. Нативное событие сообщает только факт редактирования, без якоря поля в координатах окна. Для локальной капсулы над полем нужен нативный якорь, обновляемый при zoom, прокрутке, повороте и показе клавиатуры; приблизительное позиционирование в JS не используется.

## Историческая проверка до полировки (не является приёмкой текущего состояния)

Ошибка записи проверена на синтетической странице: drawing временно сохранён в backup, его путь занят пустым каталогом. При штрихе показано «Не удалось сохранить страницу. Не закрывайте документ и повторите попытку.» (`write-error.png`, текст целиком читается). Каталог удалён, backup возвращён, выполнен новый штрих для повторного сохранения. Это инъекция ошибки назначения, не заполнение диска. Также просмотрены реальные карандашный и маркерный штрихи (`marker-stroke.png` содержит карандаш, `marker-actual.png` — широкий полупрозрачный маркер), частичное стирание (`erase-result.png`) и открытый системный выбор цвета (`color-open.png`).

Полная зона B ещё не принята. Нет настройки типа/маски лассо и полного визуального соответствия плавающим панелям Goodnotes. Для ластика добавлен `eraserAutoReturn`; владелец документа возвращает предыдущий инструмент по `EditorPageRibbon.onToolEnd`; возврат проверен реальным жестом WDA (`eraser-return.png`). Жест pinch, ошибки записи диска и узкое окно требуют отдельной нативной приёмки. Программный масштаб UIScrollView проверен временным `zoomScale=2` (`zoom-programmatic.png`), тестовая настройка удалена. Системный PencilKit не предоставляет произвольную маску выбора объектов: соответствующие неработающие переключатели не показаны.

Через системный photo picker выбрано стандартное фото симулятора, объект перемещён и удалён через нативное контекстное меню. Просмотрены `photo-picker.png`, `photo-inserted.png`, `photo-moved.png`, `photo-delete-menu.png`, `photo-deleted.png`; после удаления manifest содержит только текстовый объект. Снимок вставки имеет повёрнутую ориентацию capture, последующие снимки — портретные. Масштабирование объекта жестом ещё не проверено. После отключения автоматических inset у UITextView поле остаётся в координатах страницы (`text-native-inset.png`); foreground native rebuild завершился с exit=0. Стеклянные панели письма, текста и истории просмотрены в `glass-panel.png`, `glass-landscape.png`, `text-glass.png`, `text-glass-portrait.png`, `history-glass.png`: подписи помещаются, color picker больше не растянут на ширину экрана. Это не утверждение полного соответствия Goodnotes.

На назначенном симуляторе проверена прокрутка синтетического документа из шести страниц: grid, blank, ruled, dots (включая жёлтую бумагу), PNG и PDF. PNG отображается с сохранением пропорций, PDF — с белыми полями и синтетическим оранжевым прямоугольником. Просмотренные снимки: `~/Pictures/OpenCode/notes-by-blum/editor/image-background-final.png`, `assets-check.png`, `glass-panel.png`. После создания повреждённого drawing показано сообщение «Не удалось открыть страницу. Закройте документ и попробуйте снова», SHA-256 файла остался прежним. Это проверка ошибки чтения, не ошибки записи диска. `wda.py` не содержит команды pinch. Пересборка после изменения packagePath завершилась с exit=0. В публичном заголовке установленного SDK `PencilKit.framework/Headers/PKLassoTool.h` объявлен только `init`, без типа выделения и маски захвата.
