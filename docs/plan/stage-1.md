# Этап 1: ТЗ и разделение работы

Личное iPad-приложение для рукописных заметок «notes by Blum». По UX и структуре это клон Goodnotes 7: пользователь переходит с Goodnotes без привыкания. Приложение только для себя, не публикуется, сервера нет, всё хранится локально. Документацию, тексты интерфейса и коммиты пишем на русском.

## Главный принцип: максимум нативного, современный Apple UI

- Нативные системные элементы и Liquid Glass (iPadOS 26+, Xcode 27.1). Минимальная версия — iPadOS 26.
- Системные контролы не имитируем самописными RN-view. Тулбары, кнопки, меню, поповеры, sheet, сегменты, слайдеры, переключатели, color picker, поиск и контекстные меню берём из `@expo/ui` и Expo-пакетов. Свой Expo-модуль пишем только там, где их не хватает.
- Стекло — `glassEffect`/`GlassEffectContainer` в SwiftUI или `expo-glass-effect`. Навигация — нативные стеки и сплит-вью. Иконки — SF Symbols. Фото — системный PHPicker. Цвет — системный `ColorPicker`. Экспорт — системный share sheet.
- Раскладку, порядок и состав элементов берём из Goodnotes, визуальный язык — из Apple HIG (Liquid Glass): плавающие стеклянные панели поверх контента, капсулы, системные материалы.
- Перед реализацией проверяй актуальную документацию Expo SDK 57 (`@expo/ui` SwiftUI, expo-glass-effect, expo-router) и Apple SwiftUI.

## Кроссплатформенность

- Экраны, навигация, состояние, хранение и логика — на TypeScript, общие для платформ.
- Платформенное прячем за TS-интерфейсами Expo-модулей. Сейчас пишем только iOS-реализацию (PencilKit), но в общем коде не должно быть iOS-специфичных допущений.
- Android в этом этапе не собираем, но и не блокируем.

## Архитектура

- **Чернила.** PencilKit `PKCanvasView` в Swift-модуле `NotesCanvas`. Системный `PKToolPicker` не используем: тулбар свой, как у Goodnotes. Инструменты — `PKInkingTool` (pen/monoline/fountain/marker/pencil), `PKEraserTool` (bitmap/vector, ширина), `PKLassoTool`. `PKDrawing` сохраняется и загружается нативно, штрихи не идут через JS-мост. `drawingPolicy`: рисует Pencil, палец скроллит и зумит; при настройке «рисовать пальцем» и в Debug на симуляторе — `.anyInput`.
- **Хранение.** Пакет на документ: `Documents/Library/<id>.notebook/` — `manifest.json`, `pages/<pageId>.drawing`, `pages/<pageId>.json` (изображения и текстовые поля), `assets/`, `thumbnails/`. Запись атомарная (temp + rename). Папки иерархические. Индекс библиотеки в expo-sqlite — кэш, который перестраивается из пакетов.
- **Редактор.** Живые канвасы только для видимых страниц ±1. Вертикальная прокрутка, зум, автосохранение. Обложка документа строится из первой страницы.
- Без лишних абстракций и дублирующего состояния: тонкий репозиторий поверх sqlite и файловой системы.

## Объём этапа 1

1. **Библиотека** (01–09, 41): sidebar (Документы, Избранное), меню аккаунта (Настройки, Корзина), большой заголовок, поиск по названиям, фильтр Все/Документы/Папки, «+ Создать» (Блокнот, Папка, Импорт PDF/изображения; прочие пункты Goodnotes не показывать), меню вида (выбор элементов → Переместить/В корзину; сетка/список; сортировка с направлением), адаптивная сетка (портрет 4 колонки, ландшафт 5–6) и список, вход в папку, меню документа (переименование, Дублировать, Переместить, В корзину), меню папки (переименование, цвет, Переместить, В корзину), избранное, корзина (восстановить, удалить навсегда).
2. **Создание блокнота** (нативный sheet, по образцу 42–42d): название, обложка (несколько цветов), бумага — без линий / линейка / клетка / точки, белая / жёлтая, размер A4 / Letter, портрет / ландшафт.
3. **Редактор** (20–26d, 31–31h, 33–33c, 36–40):
   - полоса вкладок открытых документов: Home и вкладки с ×; у активной ⌄ открывает меню документа (39);
   - плавающая стеклянная строка: слева боковая панель страниц (38/38b) и чип «Режим редактирования / Только чтение»; в центре Лассо, Письмо, Ластик, Изображение, Текст; справа Добавить страницу (36), Поделиться (экспорт PDF), Ещё (37, только реализуемые пункты);
   - подпанель Письма (22–25, 23c): Ручка (повторный тап — поповер типа и слайдеров), Карандаш, Маркер; 3 пресета толщины и пресеты цветов, свои для каждого инструмента; поповер цвета с системным picker; пресеты сохраняются;
   - Ластик (26–26d): Точный / Стандартный / Для штрихов, три размера, «Очистить страницу», «Автоперекл. на предыдущий инструмент»;
   - Лассо (33c): штатный `PKLassoTool`;
   - Изображение: PHPicker → объект на странице; перемещение, масштаб, удаление через контекстное меню;
   - Текст (31–31h): тап создаёт поле; капсула формата — цвет, размер, шрифт, B/I, выравнивание; поле редактируется и перемещается; пустое поле исчезает при тапе мимо;
   - капсула Отмена/Повторить слева сверху;
   - не делать и не показывать заглушками: фигуры, элементы, клейкие заметки, лазер, ленту, Draw Shape, аудио, ИИ, поиск по рукописи, аксессуары.
4. **Настройки** (10–12): направление прокрутки, «рисовать пальцем», открывать документы в новых вкладках. Только то, что реально работает.

Не добавлять: сервер, подписки, аналитику.

### A — библиотека и файлы
- Репозиторий документов: формат пакета, атомарная запись, индекс sqlite и его перестройка, папки, избранное, корзина, дублирование, перемещение.
- Экран библиотеки целиком (п. 1), вход в папку, поиск по названиям, корзина.
- Меню «Создать» и sheet создания блокнота (п. 2), создание папки.
- Импорт изображения и PDF: пакет с исходником в `assets/` и страницами с фоном `{ kind: 'pdf', page }` или `{ kind: 'image', asset }`. Отрисовку фона делает B.
- Обложки в библиотеке: показывает `thumbnails/cover.png`, если есть, иначе цвет обложки. Файл обложки создаёт C.

### B — редактор: канвас и инструменты
- Модуль `NotesCanvas`: PencilKit, инструменты, сохранение и загрузка `PKDrawing`, undo/redo, `drawingPolicy`, фон страницы под канвасом (бумага всех типов, фон PDF/изображения).
- Лента страниц редактора: вертикальная прокрутка, зум, живые канвасы только для видимых ±1, автосохранение.
- Центральная группа строки инструментов и подпанели: Лассо, Письмо (+ поповеры типа ручки и цвета), Ластик (+ настройки), Изображение, Текст (+ капсула формата), капсула Отмена/Повторить.
- Объекты страницы: изображения и текстовые поля в `pages/<pageId>.json`.

### C — оболочка редактора, страницы, экспорт, настройки
- Полоса вкладок открытых документов и меню документа (39).
- Левая и правая группы строки инструментов: боковая панель страниц (38/38b) и её меню, чип режима, Добавить страницу (36), Поделиться, Ещё (37).
- Нативный рендер: миниатюры страниц и обложка `thumbnails/cover.png` (бумага + `PKDrawing.image` + объекты), экспорт PDF в системный share sheet. Код рендера — отдельные Swift-файлы в модуле `notes-canvas`; отрисовку бумаги переиспользовать из общего файла каркаса, не дублировать.
- Экран настроек (п. 4) и хранение настроек, которые читает редактор.

### D — ревью и интеграция

### Правила для всех
- Общие контракты из каркаса (`src/shared`, TS-интерфейс `modules/notes-canvas/index.ts`) меняй только при необходимости и с описанием в коммите. Чужие зоны не реализуй; если нужна правка в чужой зоне, сделай минимальную и опиши её в отчёте.
- Не трогай `openspec/`, `docs/reference/`, этот файл, файл `1100` в корне и чужие worktree.
- Физический iPad занят: там WebDriverAgent и iproxy на порту 8100, не трогай их и процессы xcodebuild/iproxy тестов, не меняй файлы в `~/Developer/tools/`. Чужой Metro Style Flip на 58081 не трогай.
- Ввод в симуляторе (Simulator.app в этом Xcode нет): запусти WDA на своём симуляторе в фоне — `~/Developer/tools/sim-wda.sh <UDID> <порт WDA> > <лог> 2>&1`, затем `WDA_PORT=<порт> ~/Developer/tools/wda.py tap X Y | swipe X1 Y1 X2 Y2 [сек] | ltap X Y [сек] | type ТЕКСТ | tree | shot OUT.png | orient LANDSCAPE|PORTRAIT | size`. Координаты в pt; `swipe` — это штрих пальцем (в Debug на симуляторе канвас принимает `.anyInput`). Команду `snap` не используй. В конце останови свой WDA.
- Только свой симулятор и свой порт Metro (`expo run:ios --device <UDID> --port <порт>`). Свои процессы отслеживай и в конце останавливай. Длинные команды — в фоне с логом.
- Проверки: `npm run typecheck`, `npm run lint`, сборка под свой симулятор.
- UI-гейт: пройти свои сценарии в симуляторе, снять скриншоты (`xcrun simctl io <UDID> screenshot`) в `~/Pictures/OpenCode/notes-by-blum/<агент>/`, просмотреть каждый image-capable read-ом, сравнить с референсом, проверить портрет и ландшафт, исправить дефекты. Реальные сценарии проходи через WDA: тапы по своим контролам и штрихи `swipe` на канвасе.
- Коммить законченные части в свою ветку: короткий русский заголовок, только свои файлы, без `git add -A`, без push, rebase, amend и force. Если проверка заблокирована — пометка «не проверено» в заголовке и причина в теле.
- Отчёт: что реализовано и что нет (с причинами), изменения контрактов, результаты проверок, пути к скринам с наблюдениями, хеши коммитов.
