# notes by Blum: от Windows до первой тестовой установки

## Сейчас

Название выбрано: **notes by Blum**. Своего Mac нет; Apple Developer и GitHub ещё не созданы. В проекте нет чужих аккаунтов, сертификатов, ключей или фиктивных контактов. Сначала нужно получить настоящую проверку сборки: подготовленные workflow сами по себе ничего не подтверждают.

## Шаг 1. Проверка, для которой пока не нужен Apple Developer

1. Создайте аккаунт на [GitHub](https://github.com/signup).
2. Создайте репозиторий `notes by Blum`. Публичность выбирайте осознанно: публичный репозиторий раскрывает исходники. Условия и лимиты macOS runner смотрите в своём аккаунте; платные ресурсы не включайте автоматически.
3. Загрузите **содержимое** папки `notes by Blum` в корень репозитория, включая скрытую `.github`. В корне должны быть `NotesByBlum.xcodeproj`, `Blumbum/`, `scripts/` и `.github/`, без лишней внешней папки. Через браузер можно загрузить ZIP-распакованные файлы; проверьте, что `.github/workflows/ios.yml` тоже попал в репозиторий.
4. Откройте Actions → **iOS build and tests** → Run workflow. Для проверки контакты и подписка пока не нужны.
5. Workflow выбирает установленный стабильный Xcode с SDK 26 или новее, проверяет пакет, запускает XCTest и UI-сценарий на iPhone и iPad, затем собирает Release для iOS без подписи. Недостающий runtime или ошибка компиляции останавливают процесс.
6. В `ios-test-results` сохраняется `.xcresult`, включая screenshot-вложение UI-теста. Оно показывает реальный симулятор, а не нарисованный макет. Само наличие workflow не означает, что снимок или успешная сборка уже существуют.
7. Передайте ссылку на репозиторий и результат Actions в этот чат. Можно подключить GitHub для чтения ошибок. Для публикации изменений в репозиторий понадобятся соответствующие права или GitHub CLI; одно подключение не гарантирует возможность загрузки исходников.

## Шаг 2. Аккаунт Apple и реальные данные владельца

Для распространения создайте Apple ID и вступите в [Apple Developer Program](https://developer.apple.com/programs/enroll/). Доступность регистрации, условия и оплату проверьте для своей страны и типа владельца. Имя физического лица или организации в магазине определяется аккаунтом; выдумывать его в проекте нельзя.

Нужны также:

- рабочий публичный email поддержки;
- публичные HTTPS-страницы поддержки и политики конфиденциальности;
- уникальный Bundle ID, зарегистрированный в вашем Apple Developer;
- запись приложения notes by Blum в App Store Connect и проверка доступности названия;
- месячная и годовая подписки в одной группе, договоры/налоги/банковские данные.

В `Blumbum/Resources/AppConfiguration.json` заполните четыре поля. Черновики документов находятся в `docs/store/`; они требуют реальных контактов и публикации. Приложение добавляет ссылки автоматически. Release-сборка не разрешает покупку при незаполненных реквизитах; Debug позволяет проверять StoreKit локально.

Проверка перед загрузкой:

```text
python scripts/release_preflight.py --check-urls
```

Сейчас она ожидаемо не проходит: контактов и опубликованных страниц ещё нет.

## Шаг 3. Подпись и TestFlight

Проект содержит отдельный ручной workflow **Signed build and TestFlight upload**. Он сначала требует успешные тесты, затем проверяет публичные ссылки, собирает архив, экспортирует IPA и отправляет сборку в App Store Connect. Он не отправляет приложение на App Review и не делает публичный релиз.

В GitHub создайте Environment `testflight`. При доступности настройте required reviewers, чтобы передача подписанной сборки требовала вашего подтверждения. В Environment добавьте Variables:

| Variable | Значение |
|---|---|
| `APPLE_TEAM_ID` | Team ID вашего аккаунта Apple Developer |
| `APP_BUNDLE_ID` | Точный зарегистрированный Bundle ID приложения |

В Environment Secrets добавьте:

| Secret | Что содержит |
|---|---|
| `IOS_DISTRIBUTION_P12_BASE64` | Base64 сертификата Apple Distribution **с приватным ключом**, экспортированного в .p12 |
| `IOS_DISTRIBUTION_P12_PASSWORD` | Пароль .p12 |
| `IOS_PROFILE_BASE64` | Base64 App Store distribution provisioning profile для выбранного Bundle ID |
| `ASC_PRIVATE_KEY` | Полный текст приватного .p8 Team API key App Store Connect |
| `ASC_KEY_ID` | ID этого API-ключа |
| `ASC_ISSUER_ID` | Issuer ID |

Получение сертификата с ключом и provisioning profile — отдельный шаг настройки подписи. Можно сделать его при временном доступе к Mac. Для нового аккаунта нельзя просто скачать .cer и подставить вместо .p12: нужен соответствующий приватный ключ. API-ключ должен иметь достаточные права на загрузку сборок вашего приложения; роль и доступы настраиваются владельцем.

**Не отправляйте пароли, .p12, .p8 и значения Secrets в чат или репозиторий.** Они используются только в настройках CI. Workflow устанавливает временный keychain, проверяет соответствие профиля и удаляет материалы после выполнения. Он ещё не запускался на реальном аккаунте; первый запуск может выявить дополнительные требования профиля или Xcode.

После успешной загрузки дождитесь обработки сборки Apple, заполните Export Compliance и включите внутреннее тестирование TestFlight. Для внешних тестировщиков может потребоваться Beta App Review. Для своего iPhone/iPad устанавливайте сборку через приложение TestFlight; артефакт симулятора из шага 1 на устройство не устанавливается.

## Шаг 4. До App Review

Пройдите чек-лист `RELEASE.md`: реальный Apple Pencil, сохранение и перенос данных, PDF, подписки Sandbox, экраны на разных устройствах и доступность. Подготовьте настоящие скриншоты, App Privacy, возрастной рейтинг, поддержку и review notes. Загруженная сборка не означает автоматическое одобрение.

На 13 ноября 2026 года загрузка требует Xcode 26 и iOS SDK 26 или новее: [официальное требование](https://developer.apple.com/news/upcoming-requirements/?id=04282026a). Минимальная поддерживаемая версия самого приложения остаётся iOS/iPadOS 17.
